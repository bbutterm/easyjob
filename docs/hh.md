# Адаптер hh.ru: вакансии, резюме, поиск

Два способа читать hh.ru, оба на сервере; браузер пользователя к hh.ru не обращается,
его куки наружу не уходят.

| Режим `HH_MODE` | Как | Когда |
| --- | --- | --- |
| `browser` (по умолчанию) | Chromium на сервере (Playwright) открывает страницу как обычный посетитель: `hh.ru/vacancy/<id>`, `hh.ru/resume/<hash>`, `hh.ru/search/vacancy?text=…`. Поля читаются из разметки `data-qa`, видимый текст страницы отдаётся модели (`page.extract`). Ключей и договора с hh не нужно. 2–6 с на страницу | по умолчанию; когда API недоступен или нежелателен |
| `api` | Публичный API `api.hh.ru` (вакансии и поиск; резюме только со страницы). ~0,3 с, стабильный формат | если есть договор с hh или нужна скорость |
| `auto` | Сначала браузер, при его недоступности или отказе — API | смешанно |

## Модель на странице (`page.extract`)

Видимый текст страницы содержит меню, подвал, «похожие вакансии». Задача модели
`page.extract` (этап `pre_interview`, открытые веса по общей политике) получает адрес,
ожидаемый тип (вакансия/резюме) и текст, а возвращает только саму вакансию (название,
компания, текст дословно) или поля резюме. Без добавления фактов; `kind: none`, если на
странице капча, вход или ошибка. Ответ проверяется по схеме, обрыв — `malformed_response`.

`HH_EXTRACT=auto` (по умолчанию) — модель вызывается только когда разметка страницы не
распозналась (партнёрская страница, изменившаяся вёрстка); `model` — всегда; `off` —
никогда, тогда остаётся сырой текст с пометкой. Вызов учитывается в расходе как задача
подготовки; текст страницы в базу не пишется и клиенту не возвращается. В интерфейсе
подпись: «по разметке страницы», «поля выделила модель <провайдер · модель>» или «сырой
текст страницы, модель не ответила». Ошибка модели импорт не роняет.

Модуль `server/lib/adapters/hh-browser.js`: один браузер на процесс, не больше двух вкладок
одновременно, закрытие после 30 с простоя, картинки/шрифты/медиа не грузятся, обычный
User-Agent Chrome (`HH_BROWSER_UA`), свой путь к Chromium — `HH_BROWSER_PATH`. Капча,
редирект на вход, 403/429 → `blocked`; капча не решается и не обходится. Регион в поиске:
таблица крупных городов → `area=`, остальные города добавляются словом в запрос.

Установка на сервере: `npm ci` ставит `playwright`, затем `npx playwright install --with-deps
chromium` (Linux) — около 300 МБ. Без Chromium сервер отвечает `browser_unavailable` (503),
а в `HH_MODE=auto` уходит в API.

## Модуль API (`server/lib/adapters/hh.js`)

## Что делает

| Действие | Как | Маршрут |
| --- | --- | --- |
| Вакансия по ссылке `hh.ru/vacancy/<id>` (в том числе `spb.hh.ru`, `hh.kz`, `hh.uz`, `hh.by`, `headhunter.kz/kg`) | Карточка из публичного API `GET api.hh.ru/vacancies/{id}`: название, компания, регион, зарплата, опыт, занятость, график, описание без тегов, ключевые навыки | `POST /api/vacancies/import-url` — распознаёт hh-ссылку сам; при недоступности API падает на общий импорт страницы (`docs/vacancy-import.md`) |
| Резюме по ссылке `hh.ru/resume/<hash>` | Чтение публичной страницы (резюме должно быть открыто «всем» в настройках видимости на hh.ru) и разбор по разметке `data-qa`: должность, опыт с компаниями и периодами, навыки, «о себе», образование | `POST /api/resumes/import-url` → предпросмотр; сохраняется только после подтверждения через `POST /api/resumes` |
| Поиск подходящих вакансий | `GET api.hh.ru/vacancies?text=…&area=…` (20 на страницу, до 20 страниц, кэш 10 минут). Запрос по умолчанию — профессия и два навыка резюме. Регион можно указать названием: разрешается через `GET api.hh.ru/suggests/areas` | `GET /api/jobs/search?text&area&page&resumeId`, `GET /api/jobs/areas?text` |
| Похожесть на резюме | Пересечение основ слов резюме (профессия, навыки, должности, описания опыта) с названием и сниппетом вакансии; совпадение в названии и в основных навыках весит больше. Число 0..100 и список совпавших слов. Это подсказка для сортировки, **не оценка модели** и не «процент соответствия» | в ответе поиска: `score`, `why` |

В интерфейсе: экран `#/jobs` («Поиск вакансий»), блок «Импорт с hh.ru по ссылке» на
`#/resume/upload`, кнопка «Найти вакансии на hh.ru» на списке вакансий и форме вакансии.
«Создать подготовку» из результата поиска переносит ссылку и выбранное резюме в форму
вакансии и запускает импорт; дальше обычный путь: проверка текста → сопоставление.

## Что уходит на hh.ru

- Идентификатор вакансии или хэш резюме из ссылки, которую вставил пользователь.
- При поиске — текст запроса, регион и номер страницы. Само резюме не отправляется:
  запрос из него собирается на сервере, ранжирование тоже на сервере.
- Заголовок `User-Agent: Easyjob/1.0 (<контакт>)` — hh требует контакт приложения;
  адрес задаётся `HH_CONTACT`. Токен `HH_TOKEN` (OAuth приложения) не обязателен и не
  нужен для перечисленных публичных методов.

## Что не делается

- **Капча и вход не обходятся.** Если страница резюме отдала проверку «не робот», 403
  или 429, ответ `{ ok:false, code:'blocked' }` с советом выгрузить резюме с hh.ru в PDF
  или DOCX и загрузить файлом. Закрытые резюме недоступны: API hh отдаёт резюме только
  владельцу по OAuth, что требует зарегистрированного приложения.
- Ничего не публикуется, отклики не отправляются, аккаунт пользователя не нужен.
- Страницы hh.ru в общий импорт по ссылке не идут: они требуют JavaScript и часто отдают
  капчу, поэтому вакансии берутся из API.

## Правовая сторона

Условия hh.ru: публичные методы API доступны без договора для некоммерческого
использования при указании контакта в `User-Agent`; коммерческое использование и
методы с данными соискателей требуют соглашения с hh и регистрации приложения
(`dev.hh.ru`). Перед запуском продукта на реальных пользователях это соглашение нужно
оформить; до этого адаптер рассчитан на проверку и личное использование. Разбор
страницы резюме читает только то, что владелец открыл всем; условия hh запрещают
массовый сбор данных — адаптер читает одну страницу по явной ссылке пользователя,
без обхода.

## Переменные окружения

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `HH_CONTACT` | `support@easyjob.local` | контакт в `User-Agent` (обязательно заменить на реальный) |
| `HH_TOKEN` | пусто | токен приложения, если оформлен |
| `HH_API_BASE` | `https://api.hh.ru` | адрес API; в проверках подменяется локальным сервером |
| `HH_SITE_BASE` | `https://hh.ru` | адрес сайта для страниц резюме; в проверках подменяется |

Ограничения: ответ до 2 МБ, 12 секунд, отмена при обрыве запроса клиента. Ошибки
hh (сеть, не JSON, 5xx) отдаются как `{ ok:false, code }` с общим текстом, без
пересказа ответа сервиса.

## Проверки

`npm run test:hh:browser` — 29 проверок: поддельный hh.ru, страницы которого собираются
JavaScript-ом (без браузера пусто), Chromium сервера читает вакансию, резюме и выдачу;
страница без разметки → поля выделяет модель (на заглушке), меню сайта отброшено; капча,
403, 404, отмена; режимы browser/auto/api через маршруты; расход учтён, текст страницы не
хранится; браузер закрыт после работы. В `npm run test:live` — то же в интерфейсе с подписью
«поля выделила заглушка модели».

`npm run test:hh` — 47 проверок: распознавание ссылок, карточка из API, разбор
страницы резюме (компания перед должностью, периоды, навыки, образование, капча,
страница без разметки), ранжирование, поиск с регионом и кэшем, маршруты против
поддельных API и сайта на loopback (без куки, только текст запроса наружу, чужое
резюме → 404). В `npm run test:live` — сквозной путь в браузере: капча → предпросмотр
резюме → сохранение → автоматический поиск по резюме → «Создать подготовку» →
импорт через API. Настоящий hh.ru в проверках не вызывается; живая проверка —
вставить реальную ссылку на сервере с `HH_CONTACT`.
