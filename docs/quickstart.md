# Quick Start: первая подготовка

## Точный пользовательский путь

1. Открыть HTTP-продукт и зарегистрироваться или войти. Новая регистрация открывает
   `#/quickstart`; первый вход без локального статуса и без сохранённой работы — тоже.
   Повторный вход ведёт на обзор. Если до внедрения уже есть резюме, вакансии или
   подготовки, вход ведёт на обзор. Из меню можно продолжить или начать мастер заново.
   Прямой вход гостя на этот маршрут ведёт к форме входа; в `file://` — на демо-обзор.
2. **Добро пожаловать.** Прочитать порядок хранения и передачи данных AI, открыть
   «Обработка данных» при необходимости. «Продолжить» фиксирует ознакомление.
   Это информационный шаг, а не серверный юридический журнал согласий.
3. **Резюме.** Выбрать существующее или ввести название и текст (от 40 символов).
   «Сохранить резюме» вызывает `POST /api/resumes`, без AI. Результат остаётся на
   текущем шаге с отметкой «Готово»; затем нажать «Продолжить».
4. **Проверка резюме.** Прочитать объяснение AI и нажать «Проверить резюме с AI»:
   `POST /api/resumes/:id/review`. Прочитать рекомендации, которые не применяются
   автоматически. Если проверка уже есть, повторный вызов не нужен.
5. **Вакансия.** Выбрать существующую или вставить должность, компанию и текст
   (от 40 символов). `POST /api/vacancies` уже выделяет требования с AI. Подгружается
   полный список вакансий, включая сохранённые без подготовки.
6. **Требования и сопоставление.** «Создать подготовку» вызывает `POST /api/preps`
   с выбранными источниками. Сервер выделяет отсутствующие требования и выполняет
   match. Для устаревшей/незавершённой подготовки используется `/rebuild`. Готовый
   match предлагается открыть без повторной генерации. Затем «Продолжить».
7. **Вопросы.** `POST /api/preps/:id/questions`. Показан первый вопрос и ссылка на
   все вопросы. Необязательно написать ответ и сохранить через
   `PUT /api/preps/:id/answers`. Ответ отмечается сохранённым только после успеха API.
8. **Обратная связь на ответ.** «Получить обратную связь с AI» вызывает
   `POST /api/preps/:id/feedback` по первому вопросу: сильные стороны, пробелы и вариант
   формулировки, без баллов. Нужен сохранённый ответ с предыдущего шага; без него
   показывается подсказка вернуться. Результат хранится в подготовке.
9. **Текстовая тренировка.** «Открыть текстовую тренировку» открывает существующий
   `#/prep/:id/interview`. Нажать «Начать интервью». Один переход по ссылке не
   означает выполнения: нужна успешная первая реплика. Вернуться через
   «Продолжить Quick Start» в меню (на мобильном — кнопка «Меню»).
10. **Что дальше.** Прочитать отдельное объяснение live/STT. Следующее действие —
   открыть помощник и проверить настройки, разрешения и согласие участников.
   «Завершить Quick Start» возвращает на обзор, не заявляя готовность live/STT.

На каждом шаге видны номер из девяти, текущий этап и состояния «Готово»,
«Пропущено», «Впереди». Готовность вычисляется из Store после ответа сервера,
не из посещённых URL. Устаревшее сопоставление не считается готовым. Пустая запись
интервью без реплик тоже не считается начатой тренировкой.

«Назад» сохраняет результаты. «Пропустить этот шаг» не имитирует выполнение;
для зависимых действий показывается необходимость вернуться к исходникам.
«Продолжить позже» ведёт на обзор. Перезапуск сбрасывает этапы ознакомления и
пропуски, сохраняя настоящую работу. Существующие результаты снова отмечаются
готовыми. Все обычные ссылки остаются доступны; завершение запроса не возвращает
насильно в мастер. На экране одна основная кнопка, остальные действия вторичные.

## Режимы AI

Pre-interview в текущей production-конфигурации использует OpenRouter. Экран также
показывает описание режима текущего сервера: локальная заглушка явно обозначена.
Текстовая тренировка вызывает существующий `interview.turn`; её провайдер задаётся
существующей маршрутизацией. Live/STT — отдельный контур: мастер не включает запись,
не настраивает провайдеров, не обещает работающий STT при mock/отсутствии конфигурации.
Роутинг провайдеров и секреты не менялись.

## Хранение и изоляция

Серверного механизма пользовательских предпочтений сейчас нет. Клиентский ключ:
`easyjob:quickstart:v1:<URL-encoded server user id>`. Значение содержит только
`step`, массивы номеров `completed`/`skipped`, `finished`, `timestamp`. Произвольные
поля из localStorage отбрасываются. Названия, ID источников, тексты, ответы,
пароли и токены в этот ключ не записываются. Выбор источников и черновики живут
в памяти вкладки; после перезагрузки используется активная подготовка либо первые
сохранённые источники. Готовность заново проверяется по данным сервера.

При выходе очищаются владелец, черновики и данные в памяти; отложенные сохранения
ответов отменяются. Исторический компактный статус остаётся под ID прежнего
пользователя, чтобы повторный вход не запускал мастер заново. Другой аккаунт
читает только собственный ключ. Запоздалые ответы Quick Start после смены владельца
не применяются. Перед записью проверяется пользователь через `/api/me`, в том числе
на случай истёкшей сессии или смены cookie в другой вкладке.

Ключ `easyjob:auth:change` содержит только случайный маркер времени. Событие смены
входа/выхода очищает данные и мастер в других открытых HTTP-вкладках и ведёт их на
форму входа. Это не хранение сессии или секрета.

Компромисс MVP: статус не синхронизируется между устройствами. Очистка хранилища
или новый браузер могут снова открыть мастер у аккаунта без сохранённой работы.
При запрете localStorage мастер работает в памяти, но не помнит посещение после
перезагрузки; межвкладочное уведомление также недоступно, проверка `/api/me` перед
действиями остаётся. Локальные статусы доступны владельцу браузерного профиля;
они не содержат содержимого пользовательских документов.

## Проверки

- `npm run test:quickstart`: без сокетов, реальные auth/API handlers, SQLite в памяти,
  настоящие Store/API adapters и QuickStart, AI mock. Первый/повторный вход,
  все действия, ошибка и повтор, ответ, реальное начало интервью; пропуск/назад/
  позже/перезапуск; старые данные и устаревший match; выход, смена аккаунта,
  поздний ответ, несовпадение серверного владельца, событие другой вкладки;
  `file://`, испорченный/запрещённый localStorage и отсутствие чувствительных полей.
- `npm run test:quickstart:browser`: HTTP + Chromium, настоящая регистрация и API;
  1440/390/360 px, один primary action, контроль переполнения и целей от 44 px,
  клавиатура Enter и фокус заголовка, reduced motion, ошибка review и retry,
  полный путь, старые данные после повторного входа, навигация и смена аккаунта.
- `node tests/auth-browser.test.js`: обновлён ожидаемый маршрут после первого
  входа/регистрации; прежние проверки admin, auth, клавиатуры и мобильных экранов.
- `npm run test:all`, `npm run build`, `git diff --check`.

Ручной чеклист: пройти сценарий с собственными тестовыми текстами; выйти и войти;
переключить аккаунт и вкладку; проверить выбор других источников, перезагрузку,
ошибку/лимит API, пропуск обязательного исходника и возврат назад; пройти Tab,
Shift+Tab, Enter, Space при 360/390 px и reduced motion; открыть нормальные разделы
во время ожидания запроса; убедиться, что mock и live/STT не названы готовыми.

В sandbox этого запуска HTTP-тесты блокируются `listen EPERM 127.0.0.1`, Chromium —
`FATAL sandbox_host_linux.cc:41 … shutdown: Operation not permitted (1)`.
Это ограничения среды, не успешное прохождение UI. Перед выпуском нужно повторить
браузерный чеклист в среде с разрешёнными сокетами/Chromium. Деплой не выполнялся.
