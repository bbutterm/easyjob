# Easyjob — единый гайд реального тестирования

Дата среза: 2026-09-07.

Этот документ описывает проверку двух независимых контуров:

1. **До собеседования** — OpenRouter и модели Qwen.
2. **Во время собеседования** — Cerebras для быстрых текстовых подсказок + отдельный локальный STT `whisper.cpp`.

## Текущее состояние

- OpenRouter key проверен через `GET /api/v1/models` и отвечает `200`.
- Cerebras key проверен через `GET /v1/models` и отвечает `200`.
- Ключи сохранены только на сервере в `/etc/easyjob/easyjob.env`.
- Ключи не входят в Git, frontend, Telegram, usage-таблицу и логи.
- Multi-provider routing, usage ledger и admin-панель реализованы в рабочем репозитории.
- В `main` сведены: управление контекстом (снимок подготовки, память интервью, сжатие
  `context.compact`, подтверждения FTS5), импорт вакансии по ссылке, обратная связь на ответ,
  состояние подготовки, источник каждого результата, отмена долгих операций
  (`docs/implementation-report.md`).
- Локальный полный quality gate проходит (`docs/test-report.md`).
- Для живой проверки провайдеров на сервере: `npm run smoke` — четыре задачи подготовки через
  серверный конвейер на синтетических данных; печатает провайдер, модель, статус, задержку,
  расход (сообщён/оценка), проверку схемы и оценку стоимости, без промптов и ответов.
- Публичная ссылка пока не переведена на этот новый код и остаётся на прежнем mock-конфиге.
- Реальный inference OpenRouter/Cerebras и реальное распознавание речи ещё не подтверждены.
- Политика продукта — только открытые веса: модели Qwen Plus/Max закрыты по весам и
  отклоняются `productAllowed`; для профилей нужны открытые модели Qwen (`docs/providers.md`).

Не отправляйте API keys в чат. На время проверки не используйте настоящие пользовательские резюме без необходимого согласия и правового основания.

## 1. Архитектура и ожидаемая маршрутизация

### Контур A — pre-interview

| Задача | Stage | Провайдер | Рекомендуемая модель |
|---|---|---|---|
| `resume.draft` | `pre_interview` | OpenRouter | `qwen/qwen3.7-plus` |
| `resume.review` | `pre_interview` | OpenRouter | `qwen/qwen3.8-max-0902` |
| `vacancy.parse` | `pre_interview` | OpenRouter | `qwen/qwen3.7-plus` |
| `match.requirements` | `pre_interview` | OpenRouter | `qwen/qwen3.8-max-0902` |
| `prep.card` | `pre_interview` | OpenRouter | `qwen/qwen3.7-plus` |
| `questions.generate` | `pre_interview` | OpenRouter | `qwen/qwen3.7-plus` |
| `answer.feedback` | `pre_interview` | OpenRouter | `qwen/qwen3.7-plus` |
| `interview.summary` | `pre_interview` | OpenRouter | `qwen/qwen3.8-max-0902` |

`qwen/qwen3.7-plus` выбран как экономичный структурированный вариант. `qwen/qwen3.8-max-0902` — для сложного сопоставления и reasoning.

### Контур B — live interview

| Задача | Stage | Провайдер | Рекомендуемая модель |
|---|---|---|---|
| `interview.turn` | `live_interview` | Cerebras | `qwen-3.8-27b` |
| `assistant.hint` | `live_interview` | Cerebras | `qwen-3.8-27b` |
| `screen.extract` | `live_interview` | Cerebras | `qwen-3.8-27b` |

Cerebras здесь отвечает только за текст. Он не заменяет STT.

### STT

```text
микрофон
  ↓ явное согласие
локальный whisper.cpp
  ↓ проверка/редактирование текста
interview.turn или assistant.hint
  ↓
Cerebras
```

Первая STT-версия принимает только выбранный микрофон. Системный звук, loopback, автоматическое разделение говорящих и скрытая запись не реализованы.

## 2. Реальный env-конфиг

Секретные значения должны находиться только в `/etc/easyjob/easyjob.env` с правами `600`.

Ниже конфигурационный шаблон. Значения `OPENROUTER_API_KEY` и `CEREBRAS_API_KEY` не вставляйте в Git и не отправляйте в чат.

```env
AI_PROVIDER=mock
AI_DEFAULT_PROFILE=legacy

PREP_PROVIDER=openrouter
PREP_MODEL=qwen/qwen3.7-plus
REASON_PROVIDER=openrouter
REASON_MODEL=qwen/qwen3.8-max-0902
LIVE_PROVIDER=cerebras
LIVE_MODEL=qwen-3.8-27b

OPENROUTER_API_KEY=[REDACTED]
CEREBRAS_API_KEY=[REDACTED]

AI_PROFILES_JSON={"prep":{"provider":"PREP_PROVIDER","model":"PREP_MODEL","apiKey":"OPENROUTER_API_KEY"},"reason":{"provider":"REASON_PROVIDER","model":"REASON_MODEL","apiKey":"OPENROUTER_API_KEY"},"live":{"provider":"LIVE_PROVIDER","model":"LIVE_MODEL","apiKey":"CEREBRAS_API_KEY"}}
AI_STAGE_ROUTES_JSON={"pre_interview":"prep","live_interview":"live"}

AI_TIMEOUT_MS=60000
AI_MAX_TOKENS_FIELD=max_completion_tokens
AI_MAX_OUTPUT_TOKENS=1800

# Цены OpenRouter подтверждены каталогом на 2026-09-07.
# input/output — USD за 1M токенов.
AI_PRICES_JSON={"openrouter":{"qwen/qwen3.7-plus":{"input":0.32,"output":1.28},"qwen/qwen3.8-max-0902":{"input":2.0,"output":6.0}}}
AI_PRICING_VERSION=catalog-2026-09-07

# Реальный STT подключается отдельно, не через OpenRouter/Cerebras.
STT_PROVIDER=whisper_cpp
STT_ENDPOINT=http://127.0.0.1:8080/inference
```

`AI_PROVIDER=mock` можно оставить как legacy fallback: маршруты stage будут использовать профили `prep` и `live`. До активации real mode проверьте, что JSON-конфигурация загружается без ошибки.

Стоимость Cerebras не добавлена в пример без подтверждённого тарифа конкретного аккаунта. Такие вызовы будут отмечены в админке как `Без цены`, а не как бесплатные.

## 3. Проверка провайдеров до перезапуска

Команды выполняются на сервере из deployed/current-копии или из копии репозитория с тем же env-файлом. Ключи команды не печатают.

```bash
cd /opt/easyjob/current
node tools/check-provider.js
```

Ожидается:

- выбранный profile — `prep` или stage `pre_interview`;
- provider — `openrouter`;
- model — `qwen/qwen3.7-plus`;
- HTTP-ответ провайдера без ошибки авторизации;
- корректный JSON с требованиями вакансии;
- отсутствие ключа и текста резюме в выводе.

Для live-профиля используйте отдельный безопасный smoke-запрос из server-side окружения, не вставляя ключ в командную строку и не отправляя его в Telegram. Проверяйте только короткую обезличенную фразу.

Если провайдер возвращает `401/403`, остановите тест и исправьте env. Не переключайте автоматически на другой provider: это может задвоить расходы.

## 4. Запуск Whisper.cpp для реального STT

На отдельном loopback-порту сервера или тестового компьютера:

```bash
cd /root/private/pet-interview/easyjob-audit-8P9hMe

git clone https://github.com/ggml-org/whisper.cpp.git data/whisper.cpp
cmake -S data/whisper.cpp -B data/whisper.cpp/build -DWHISPER_BUILD_SERVER=ON
cmake --build data/whisper.cpp/build --config Release -j 2
bash data/whisper.cpp/models/download-ggml-model.sh base data/whisper.cpp/models
data/whisper.cpp/build/bin/whisper-server \
  -m data/whisper.cpp/models/ggml-base.bin \
  --host 127.0.0.1 --port 8080 -l ru
```

Для более слабого CPU используйте `tiny`; для лучшего русского распознавания — `small`, если задержка приемлема. Не используйте `.en`-модель.

Не публикуйте whisper-server в Интернет. Не включайте диагностический вывод, который печатает сегменты речи. Аудио должно оставаться в памяти клиента и loopback-сервиса.

Контракт STT:

```text
POST http://127.0.0.1:8080/inference
multipart field: file
format: mono PCM16 WAV, 16 kHz
response_format=json
language=ru
temperature=0
response: {"text":"..."}
```

Для Electron:

```bash
STT_PROVIDER=whisper_cpp \
STT_ENDPOINT=http://127.0.0.1:8080/inference \
  npm --prefix desktop start
```

Проверка должна выполняться в графической сессии Linux. Пользователь вручную даёт отдельное согласие на микрофон. В интерфейсе должны быть видны `requesting`, `recording`, `transcribing`, `ready` или `error`.

## 5. Сценарий тестирования контура A — OpenRouter

### A0. Предварительная проверка

- [ ] Создан резервный snapshot текущего deployment.
- [ ] `.env`/`easyjob.env` имеет права `600`.
- [ ] Секреты не находятся в Git и frontend bundle.
- [ ] `AI_PROFILES_JSON` содержит только ссылки на env-переменные.
- [ ] `node tools/check-provider.js` проходит.
- [ ] В шапке приложения после реального запуска больше нет `mock`.

### A1. Обычный пользователь

1. Войти обычным аккаунтом.
2. Создать тестовое резюме с обезличенными данными:
   - должность;
   - 3–5 навыков;
   - 2 места опыта;
   - один измеримый результат.
3. Создать тестовую вакансию с 5–7 требованиями.
4. Запустить разбор резюме.
5. Запустить извлечение требований вакансии.
6. Создать preparation/match.
7. Сгенерировать вопросы.
8. Заполнить 2–3 ответа.
9. Запустить feedback.

Ожидается:

- все запросы идут в `pre_interview`;
- provider — `openrouter`;
- структурированные задачи используют `qwen/qwen3.7-plus`;
- match/reasoning используют `qwen/qwen3.8-max-0902`;
- ответ не выдумывает факты, отсутствующие в резюме;
- ошибки JSON не приводят к падению сервера;
- при ошибке провайдера показывается понятное сообщение;
- обычный пользователь не видит admin-панель.

### A2. Проверка качества результата

Для каждого результата отметить:

- [ ] Факты ссылаются на реальное резюме.
- [ ] Нет придуманных компаний, должностей и технологий.
- [ ] Требования вакансии не смешаны с фактами кандидата.
- [ ] `confirmed` означает наличие доказательства.
- [ ] `unclear` используется при недостатке данных.
- [ ] `missing` не превращается в категоричное обвинение.
- [ ] Вопросы относятся к вакансии.
- [ ] Feedback предлагает конкретное действие.

Рекомендуется прогнать минимум 5 обезличенных пар «резюме + вакансия» до изменения модели или prompt.

### A3. Admin cost-check

1. Войти admin-аккаунтом.
2. Открыть `Расходы AI`.
3. Выбрать `7 дней`.
4. Проверить:
   - пользователя;
   - число запросов;
   - успешные/неуспешные вызовы;
   - input/output tokens;
   - estimated cost;
   - provider/model;
   - stage `pre_interview`;
   - среднюю latency.
5. Сверить количество вызовов с фактически пройденными шагами.
6. Убедиться, что в таблице нет текста резюме, промптов и ответов.

API-проверка из admin-сессии:

```text
GET /api/admin/usage?days=7
```

Обычный пользователь должен получить `403`, анонимный запрос — `401`.

## 6. Сценарий тестирования контура B — Cerebras + STT

Этот сценарий выполняется после успешной проверки A.

### B0. Проверка Cerebras без аудио

1. Запустить короткий `interview.turn` с обезличенным текстом.
2. Проверить, что provider — `cerebras`.
3. Проверить, что model — `qwen-3.8-27b`.
4. Измерить время до первого ответа и полный latency.
5. Проверить отмену запроса.
6. Проверить повтор при временной сетевой ошибке.

Целевой критерий для первой проверки — стабильный ответ без ошибки, а не заранее обещанная конкретная задержка. Реальную latency записывать в admin usage.

### B1. Разрешение микрофона

1. Запустить Electron или HTTPS/localhost web-режим.
2. Открыть текстовое интервью.
3. Отметить отдельное согласие.
4. Нажать запись.
5. Проверить системный диалог разрешения.
6. Отказать в разрешении.
7. Убедиться, что приложение показывает `error`, не сохраняет аудио и позволяет повторить.
8. Разрешить микрофон.

### B2. Реальное распознавание

1. Выбрать правильный микрофон в ОС.
2. Произнести тестовую фразу:

   `Я работал бизнес-аналитиком пять лет и запускал автоматизацию отчётности.`

3. Нажать `Стоп`.
4. Дождаться `transcribing` → `ready`.
5. Сравнить транскрипт с произнесённой фразой.
6. Исправить текст вручную при необходимости.
7. Только после проверки нажать `Отправить фрагмент в AI`.

Критерии:

- [ ] микрофон включается только после согласия;
- [ ] виден статус записи;
- [ ] стоп освобождает audio tracks;
- [ ] аудио не появляется в файлах, localStorage, SQLite или логах;
- [ ] транскрипт можно редактировать;
- [ ] в AI передаётся только подтверждённый текст;
- [ ] Cerebras отвечает на смысл реплики;
- [ ] в usage появляется `live_interview` и `cerebras`;
- [ ] STT не записывается в AI usage как аудиофайл.

### B3. Отказ и восстановление

Проверить по отдельности:

- [ ] отказ в разрешении микрофона;
- [ ] выбран несуществующий/отключённый микрофон;
- [ ] whisper-server остановлен;
- [ ] таймаут STT;
- [ ] тишина вместо речи;
- [ ] длинная реплика более 30 секунд;
- [ ] отмена во время transcribing;
- [ ] уход со страницы;
- [ ] повтор после ошибки.

Ожидается: ошибка видна пользователю, старый аудиобуфер очищается, поздний ответ не попадает в интервью и не создаёт ложную подсказку.

## 7. Финальная проверка расходов

После выполнения A и B:

1. Открыть admin usage за 7 дней.
2. Убедиться, что есть две группы:

```text
pre_interview → openrouter → qwen/*
live_interview → cerebras → qwen-3.8-27b
```

3. Сверить количество вызовов с журналом теста.
4. Проверить estimated/reported usage.
5. Проверить `Без цены` для провайдера, если тариф Cerebras не задан.
6. Проверить, что неудачные вызовы тоже отражены.
7. Сохранить только агрегированные результаты: запросы, токены, стоимость, latency.
8. Не экспортировать резюме, промпты, ответы, аудио и транскрипты в отчёт.

Приблизительная стоимость считается так:

```text
(input_tokens × input_price + output_tokens × output_price) / 1_000_000
```

Это не бухгалтерский счёт: кэш, reasoning tokens, налоги, специальные тарифы и STT могут считаться отдельно.

## Аудит загрузки и разбора — изменения в рабочем дереве (2026-09-07)

Этот раздел уточняет исторический срез выше. По переданным данным production сейчас использует OpenRouter для pre_interview, live_interview остаётся mock. Настоящий запрос resume.review завершался примерно за 69 секунд с неразбираемым JSON. Изменения этого аудита **не развёрнуты**; production не объявляется исправленным. Для них полный quality gate в sandbox не подтверждён: HTTP/browser-проверки блокирует `listen EPERM 127.0.0.1`.

### Файлы и зависимости

- HTTP/server: выбор файла → чтение браузером → загрузка/извлечение → проверка текста → отдельная кнопка «Разобрать резюме» → анализ/результат или ошибка с повтором.
- `POST /api/resumes/extract` принимает `{name, base64}`. Байты идут только через память и stdin дочернего процесса, не сохраняются и не журналируются. Endpoint не создаёт резюме. При запуске разбора сохраняется rawText в существующей записи; обычные правила хранения/удаления резюме продолжают действовать.
- Файл до 2 МБ; извлечённый текст до 40 000 символов; для анализа минимум 40 символов. Расширение и сигнатура PDF/DOCX проверяются. Размер JSON увеличен до 3 МБ только для extraction endpoint, остальные сохраняют прежний лимит 512 КБ.
- TXT: UTF-8 (включая BOM), UTF-16LE/BE с BOM; при невалидном UTF-8 используется Windows-1251. CRLF/CR преобразуются в LF. Автоматическое определение старых кодировок неоднозначно: перед разбором проверьте кириллицу, при ошибках сохраните UTF-8. Другие кодировки не обещаны.
- DOCX: Python 3 в PATH, стандартные `zipfile`/XML. Извлекается текст основного документа, включая таблицы; изображения, комментарии, колонтитулы и встроенные объекты не анализируются. Максимум 20 МБ распакованного ZIP и 2000 записей; DTD/entities запрещены.
- PDF: Python 3 с доступным `pypdf`. До 100 страниц. Защищённый паролем PDF отклоняется. Пустое извлечение сообщает, что OCR недоступен; сканы/изображения не распознаются. Проверяйте порядок текста в многоколоночных документах. Отсутствие Python/pypdf даёт явную ошибку, а не демо.
- DOC и RTF: на проверенном окружении нет конвертеров; формат не поддерживается на сервере. Пересохраните как DOCX/PDF/TXT или вставьте текст.
- Извлечение ограничено 15 секундами, 256 МБ адресного пространства процесса и 10 CPU-секундами на Linux; одновременно до двух процессов. Python должен запускаться под пользователем приложения. Зависимости проверены только в рабочем окружении, наличие в production необходимо проверить отдельно, без установки/деплоя в рамках аудита.
- `file://` — только автономный демо-режим. Выбранный файл никогда не заменяется демонстрационным отчётом. Пример доступен лишь после очистки файла/текста. В HTTP-режиме кнопки примера нет, даже если health не ответил.

### Ожидание, отмена и источник

Pre-interview: одна попытка провайдера, общий лимит `min(timeoutMs профиля, 90000)` мс (по умолчанию 60 секунд), включая получение токена авторизации и чтение тела ответа. HTTP-обработка pre-interview ограничена 95 секундами, клиент — 100 секундами на запрос; извлечение на клиенте — 25 секунд. Разбор показывает фазу и прошедшие секунды без выдуманного процента. «Отменить» прерывает клиентский запрос; отключение клиента передаёт AbortSignal серверу. Уход с экрана также отменяет загрузку/разбор. Уже завершившееся сохранение текста отмена не удаляет.

Повтор разбора использует созданное резюме, пока текст не изменился; одновременный повтор одного resume ID на сервере возвращает 409. Ошибки различают `timeout`, `cancelled`, `provider_failure`, `malformed_response`, `unsupported_file`. При ошибке нет успешного review и нет подстановки DEMO_DATA. Usage учитывает неуспех и длительность; если провайдер не успел вернуть usage, применяются существующие оценки (это не точный счёт провайдера).

Для structured pre-interview OpenRouter передаётся capability `disableReasoning` → `reasoning: {enabled:false}`. Live routing и live reasoning не изменены. API-параметр описан в [официальной документации OpenRouter](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens); его фактическое действие на текущей Qwen требует повторного реального теста. Resume.review просит короткий ответ (до 3 элементов на массив, до 180 символов на поле) при прежнем token budget. Сервер принимает только целый JSON нужной схемы, отклоняет `finish_reason=length/max_tokens`, не вырезает JSON из произвольного текста и не делает скрытый платный repair-запрос.

У результата показаны provider/model/stage, у server mock — явная подпись о фиксированном содержании. Панель сохраняет обе stage-маршрутизации, имеет «Свернуть панель», Escape, aria-controls/expanded и прокрутку на малой высоте. Desktop: окно подсказки закрывается крестиком/Escape, окно согласия — «Выйти»/Escape. Закрытие подсказки не останавливает сессию: используйте существующее «Остановить» в управляющем окне.

### Точный checklist перед отдельным решением о деплое

1. Запустить `npm run test:resume`, `npm run test:resume:browser`, `npm run test:all`, `npm run build`, `git diff --check` в окружении, где разрешены локальные сокеты и Chromium. Smoke использует синтетические данные, desktop 1440 px/mobile 390 px, reduced motion.
2. От имени пользователя приложения проверить `python3 -c 'import pypdf, zipfile, xml.etree.ElementTree'`. Не считать доступность pypdf у root подтверждением доступности у сервиса.
3. Войти в HTTP-приложение; открыть панель, проверить pre_interview=OpenRouter и live_interview=mock; свернуть кнопкой и Escape на desktop/mobile. Проверить обычную навигацию, диалоги и возврат фокуса.
4. Загрузить синтетические UTF-8 TXT, UTF-16 TXT, DOCX и текстовый PDF; проверить извлечённые строки в textarea и отсутствие записи резюме до клика разбора. Проверить DOC/RTF, защищённый/сканированный PDF, неподходящее расширение, пустой/слишком большой файл: должна быть понятная ошибка, никакого демо-отчёта.
5. Нажать «Разобрать резюме» дважды: один активный review. Проверить фазу/секунды, успех, provider/model/stage. Проверить rawText через собственную запись API, не копируя содержимое в логи/отчёт.
6. На локальном fake-provider воспроизвести HTTP 502, JSON с обрывом, валидный JSON с finish_reason=length, зависание до заголовков и после заголовков. Pending снимается, показана соответствующая ошибка и одна основная кнопка повтора. При повторе не создаётся второе резюме с тем же текстом.
7. Во время загрузки/анализа нажать «Отменить», затем повторить; отдельно уйти с экрана. Проверить отсутствие успешного review после отмены и ошибочную usage-запись. Не ожидать отмены уже завершённого сохранения.
8. Отдельно разрешённый реальный OpenRouter smoke на синтетическом документе: проверить завершённый JSON, latency, finish reason, provider/model и usage. Не выводить prompt/raw response/API key. Без этого не утверждать, что latency и structured output конкретной Qwen подтверждены в production.
9. Проверить diff с сохранением всех предшествующих изменений. Деплой, права файлов и production-проверка — отдельная задача родительского агента.

Дополнительная найденная причина: прежний ContextStore выделял preparation только 35% общего бюджета и первым удалял rawResumeText целиком. Допустимый текст около 40 000 символов мог исчезнуть до вызова модели. Для pre-interview без истории интервью теперь выделено 90% бюджета под preparation; при потере исходного резюме/вакансии запрос отклоняется с `context_limit` до обращения к провайдеру (usage не начисляется, поскольку попытки не было). Регрессия проверяет, что полный синтетический текст действительно присутствует в запросе провайдера.
