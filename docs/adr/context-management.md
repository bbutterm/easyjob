# ADR: управление контекстом длинных сессий

Статус: принято. Дата: 6 сентября 2026. Исследование: `docs/context-research.md`.

## Контекст

Тренировочное интервью длится 30–40 минут и 100+ сообщений. Сейчас история ограничена окном
в 12 реплик, вытесненное сжимается в текстовую свёртку, которая режет реплики до 157 символов
и обрезает саму себя с начала. Итог интервью строится по тому же окну. Расход при потоковом
ответе пишется как ноль, таймаут не покрывает чтение тела, неизвестный провайдер становится
заглушкой, жёсткого предела на размер запроса нет.

Цель: снизить стоимость и задержку всей сессии без потери фактов, исправлений и качества.

## Решение

**Свой код на существующих модулях, без внешнего сервиса памяти.**

1. Точный счётчик токенов — опциональный (`@huggingface/tokenizers` + локальный
   `tokenizer.json`); без него — консервативная оценка с пометкой «неточно» и запасом.
2. Жёсткий предел проверяется **после** сериализации всего запроса, с резервом на вывод и
   служебные токены. Не помещается — запрос не отправляется, возвращается контролируемая ошибка.
3. Память интервью — отдельная таблица `context_memory`: факты с источником и статусом,
   затронутые темы, противоречия, покрытый диапазон по `sequence`, версия памяти. Публикуется
   атомарно с CAS. Итог `interviews.summary` остаётся отдельно.
4. Сжатие — задача `context.compact` через общий pipeline провайдеров и учёта: вход — прежняя
   валидная память + только новый диапазон. Порог — 70 % бюджета памяти и окна либо 8 новых
   реплик. Один compaction на интервью; сбой не портит память.
5. Evidence — SQLite FTS5 (trigram) по репликам и разделам резюме; прямые ссылки по
   `requirementId` в приоритете. Embeddings — нет.
6. Провайдеры открытых весов — профили поверх существующего OpenAI-совместимого адаптера;
   закрытые провайдеры помечены как недопустимые для продукта, fallback на них запрещён.
7. Учёт расхода — по попыткам с фазой, `requestId`, статусом «неизвестно» вместо нуля.

## Альтернативы

| Вариант | Почему отклонён |
| --- | --- |
| LangChain.js `trimMessages` | Решает только обрезку, не слои и не память; счётчик токенов всё равно свой; лишний пакет |
| LlamaIndex.TS memory | Тянет фреймворк целиком и свою модель сообщений ради блоков с приоритетами, которые пишутся в 100 строк |
| Mem0 self-hosted | Python-сервер, Docker, векторная БД и LLM-извлечение — второй контур инфраструктуры для сервиса из одного процесса на SQLite; данные резюме во внешнем сервисе |
| Letta | Агентный runtime, а не библиотека памяти; свой процесс |
| Векторный поиск | Нет доказанного преимущества над FTS5 на объёме одного интервью; новая зависимость |

## Цена сложности

- Плюс ~600–900 строк своего кода в `shared/context`, `server/lib`, миграция таблицы, тесты.
- Точность счётчика без токенизатора — оценка; это честно помечается и закладывается запас.
- Compaction — платный вызов; учитывается в бюджете сессии.

## Последствия

- Все правки — за флагом `CONTEXT_MEMORY=1`; выключен — прежнее поведение.
- Исправления дефектов таймаута, usage и неизвестного провайдера — без флага, они ошибки.
- Реальная экономия измеряется offline-replay против текущей ограниченной реализации;
  качество генераций и задержка провайдеров без ключей не измеряются.
