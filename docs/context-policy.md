# Политика контекста: что включено, какие пределы, что видит клиент

Сводка по реализованным частям плана управления контекстом (A–F). Исследование —
`docs/context-research.md`, решение — `docs/adr/context-management.md`, модель данных —
`docs/context-model.md`, каталог переменных — `docs/ai-variables.md`.

## Флаги (`.env`)

| Переменная | Значение | Что делает |
| --- | --- | --- |
| `CONTEXT_POLICY` | `policy` (по умолчанию) | Жёсткие пределы по задачам; запрос, который не помещается после сброса необязательного, не отправляется (ответ 422 с размером и пределом) |
| | `legacy` | Прежние широкие бюджеты слоёв, для сравнения. Жёсткий предел действует и здесь |
| `CONTEXT_MEMORY` | `0` (по умолчанию) | Окно последних реплик и свёртка без модели, как раньше |
| | `1` | Память интервью, сжатие `context.compact`, подбор подтверждений FTS5 |
| `AI_THINKING_OFF` | `1` | Рассуждение модели подтверждённо выключено: резерв на ответ меньше. Подтверждение — документация модели и фактический запрос |
| `TOKENIZER_JSON` | путь | Точный счётчик токенов; без него — консервативная оценка с пометкой «неточно» |

Снимок подготовки закрепляется независимо от флагов. Исправления таймаута, учёта расхода и
неизвестного провайдера — тоже без флагов: это ошибки, а не функции.

`GET /api/health` отдаёт `context: { memory, policy, evidence }`.

## Пределы по задачам (`shared/context/policy.js`)

| Задача | Вход, токенов | Резерв на ответ | Окно реплик | Обязательное |
| --- | --- | --- | --- | --- |
| `interview.turn` | 6000 | 1200 / 500 без рассуждения | 6 | профессия, текущая реплика, слабые места |
| `assistant.hint` | 4000 | 900 / 200 | 4 | вопрос собеседующего, слабые места |
| `resume.review`, `match.requirements` | 12000 | 2500 | — | опыт (и требования) |
| `interview.summary` | 16000 | 3000 | 40 | слабые места, реплики |
| `context.compact` | 10000 | 2500 | 40 | реплики диапазона, прежняя память |

Предел считается по всему сериализованному запросу: система, разделы, схема ответа,
изображение, служебные токены. Оценка без токенизатора помечается `exact: false`.
Числа — начальные гипотезы, меняются через `policyFor(taskId, overrides)`.

Порядок сброса при переполнении задан в `dropFirst`; обязательные поля не сбрасываются.
Текущая реплика и последняя реплика окна не вытесняются никогда. Подтверждения
сбрасываются последними из необязательного, память укорачивается с ранних фактов
с записью в отчёт `dropped`.

## Порядок разделов в запросе

Задача и формат ответа → профессия → снимок подготовки (опыт, навыки, требования, слабые
места, вопросы) → подтверждения по текущему вопросу → память интервью → свёртка → последние
реплики → текущий вопрос (для помощника). Стабильное впереди — ради кэша префикса.

## Память и сжатие

- Порог: 8 новых завершённых реплик после прошлого сжатия либо 70 % бюджета слоя сессии
  задачи интервью, при условии что есть что вытеснять из окна.
- Вход: прежняя память и только непокрытый диапазон, не больше 40 реплик за проход.
- Выход проверяется: ссылка на реплику с дословной цитатой или на поле документа, статус
  из пяти (`user_said`, `in_document`, `confirmed`, `conflict`, `unknown`), `supersedes` для
  исправлений. Плохие записи отбрасываются с предупреждением, годные публикуются с CAS.
- Сбой, неразборчивый ответ, переполнение, конфликт версий — память не меняется.
- Один compaction на интервью; замок с временем захвата, брошенный старше двух минут
  перехватывается. Поздние реплики остаются непокрытыми.
- Правка резюме помечает память `stale`: в запрос она не идёт, интервью продолжается на
  снимке; следующее сжатие публикует память заново под версии снимка.

## API

| Маршрут | Что нового |
| --- | --- |
| `POST /api/interviews/:id/turns` | Принимает `clientTurnId`; повтор с тем же id не создаёт дубля и отдаёт прежний ответ (`duplicate: true`). Ответ несёт `turn.seq`, `sizing`, `context` |
| поток `text/event-stream` | Событие `status` перед сжатием («Обновляю память интервью…»), затем `delta` и `done` |
| `GET /api/interviews/:id/memory` | Память владельца: версия, статус, покрытие, факты |
| `POST /api/interviews/:id/compact` | Сжать сейчас; `ran: false` с причиной, если нечего или занято |
| `POST /api/interviews/:id/finish` | Итог по памяти и подтверждениям всех ответов, `context` в ответе |

`context` в ответе: `snapshotPinned`, `sourcesChanged`, `memoryVersion`, `memoryStatus`
(`none`, `valid`, `stale`), `windowFrom`, `evidence` (источники), `evidenceVia`
(`fts`, `scan`, `direct`, `off`), `compaction` (`ran`, `ok`, `memoryVersion`,
`coveredThroughSeq`, `newFacts`, `warnings`, `trigger` или `reason`).

## Что видит пользователь

- Реплика уходит с `clientTurnId`; «Повторить» после обрыва отправляет ту же реплику с тем же
  id, а не новую.
- Пока идёт сжатие — строка «Обновляю память интервью…» вместо точек ожидания.
- После сжатия — строка «Память интервью: версия N, покрыты реплики до № M»; при устаревшей
  памяти — пометка; при сбое сжатия — причина и что реплики идут окном.
- Если резюме или вакансия изменились после начала интервью — уведомление, что интервью идёт
  на прежней версии и как перейти на новую.

## Учёт расхода

По каждой попытке: `requestId`, фаза (`main`, `compact`), провайдер и модель, токены входа,
выхода, кэша и рассуждения, стоимость (если сервис отдал), статус `reported` / `unknown` /
`not_applicable`, оценка размера и её точность, исход. Неизвестный расход — не ноль.

## Что не проверено

- Качество памяти и подтверждений на настоящей модели: все проверки идут на заглушке и
  на проверке ссылок; платных вызовов не делалось.
- Точность счётчика без токенизатора — оценка с запасом, не измерение.
- Экономия на длинной сессии — измеряется offline-replay в части G.
