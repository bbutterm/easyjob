# План доведения до рабочего продукта

Переписан 6 сентября 2026 после уточнения владельца: текущий фронтенд остаётся,
`shared/ai` считается основой серверной части. План сокращён до реального зазора между
тем, что есть, и работающим продуктом.

## Что есть

- Фронтенд: все экраны в `src/`, собранный `index.html`. Работает на демо-данных,
  запросов к серверу не делает.
- Слой запросов к модели: `shared/ai` — сборка запроса, адаптеры семи провайдеров, потоковый
  вывод, повторы, таймауты, скрытие персональных данных. Библиотека, не сервер.
- Контекст: `shared/context` — слои, бюджет, усечение.
- 171 автоматическая проверка, CI.

## Чего нет до работающего продукта

Не «только база». Пять вещей, в порядке зависимости:

1. **Сервер.** Процесс, который слушает порт, держит ключ провайдера и отдаёт результаты
   по HTTP. Без него ключ негде хранить: в браузере его увидит каждый посетитель.
2. **Вызовы из фронтенда.** Кнопки макета должны отправлять данные на сервер и показывать
   ответ модели вместо `DEMO_DATA`. Экраны уже умеют рисовать результат — меняется источник.
3. **Пользователь.** Анонимная сессия по cookie для старта, вход по ссылке на почту позже.
4. **База.** Резюме с версиями, вакансии, подготовки, ответы. SQLite для старта — одна
   строка подключения, никакой отдельной установки.
5. **Хостинг в РФ** и HTTPS.

Плюс то, чего не было с самого начала: **ни одного настоящего вызова модели**. Все адаптеры
проверены только на форме запроса.

---

## Шаг 1. Сервер с одним маршрутом (2–4 дня)

Node без фреймворка или с минимальным. Один маршрут `POST /api/match`: принимает резюме
и текст вакансии, вызывает `shared/ai` с провайдером из настроек, возвращает результат.
Ключ — только из переменной окружения.

Провайдер по умолчанию — заглушка. Так весь путь от кнопки до экрана проверяется до
получения ключа.

**Готово, когда:** `curl` на маршрут возвращает сопоставление, тест на это есть в CI.

## Шаг 2. Первая настоящая кнопка (2–3 дня)

В макете «Создать подготовку» отправляет данные на `/api/match` и рисует ответ на экране
сопоставления вместо демо-текста. Состояния загрузки и ошибки уже нарисованы — подключить.
Метка «Демо — ИИ не подключён» на этом экране убирается, когда ответ настоящий.

**Готово, когда:** сквозной тест Playwright проходит путь через сервер на заглушке.

## Шаг 3. Первый живой вызов модели (1 неделя)

Ключ российского провайдера в переменную окружения, переключить настройку — и тот же
маршрут работает по-настоящему. Здесь выяснится, верны ли формы запросов, помеченные
как несверенные.

Собрать 20 пар «резюме + вакансия» по 6–8 фокусным профессиям. Прогнать. Посчитать долю
выдуманных фактов и рубли на одну подготовку.

**Готово, когда:** не больше одного выдуманного факта на десять разборов, себестоимость
известна. **Стоп-сигнал:** если хуже после двух кругов правки промптов — менять модель,
не продолжать.

## Шаг 4. Остальные маршруты (1–2 недели)

По одному, тем же способом: вопросы, разбор резюме, реплика интервьюера с потоковым
выводом, итог интервью, карточка подготовки. Каждый — маршрут, кнопка, тест.

## Шаг 5. Сессия и база (1–2 недели)

Cookie анонимной сессии. SQLite: пользователи, версии резюме, вакансии, подготовки,
ответы. Логика устаревания отчётов переносится из `state.js` как есть. Лимит: одна
подготовка в день без оплаты.

**Готово, когда:** закрыл браузер, открыл — подготовка на месте.

## Шаг 6. Хостинг и первые люди (1 неделя)

Сервер в РФ, HTTPS, журналы с редакцией ПДн, черновик политики данных юристу. Показать
десяти знакомым из фокусных профессий, смотреть, где спотыкаются.

## Шаг 7. Оплата (1–2 недели, только если шаг 6 показал интерес)

ЮKassa для самозанятого, разовая покупка: снять дневной лимит на 7 дней. Без подписки.

---

## Итого

Шаги 1–6: около **5–8 недель** одного человека с ИИ-ассистентом, оценка грубая. Это меньше,
чем в оценке аудита, потому что фронтенд не переписывается и голос с помощником не входят.

## Что отложено осознанно

- Переход фронтенда на фреймворк — по желанию, когда экраны станет тяжело поддерживать.
- Мастер резюме с нуля, загрузка PDF и DOCX, голос — после шага 7.
- Помощник на собеседовании — заморожен, код и тесты остаются. Возврат только после
  юридического заключения.
- Вход по почте с восстановлением — когда будет что восстанавливать.

## Первое действие

Шаг 1. Могу начать сразу: сервер, маршрут `/api/match` на заглушке, тест в CI — и
подключить к нему кнопку из шага 2, чтобы весь путь ожил до появления ключа.
