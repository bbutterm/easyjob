# Подключение модели: как переключиться на другого провайдера

Провайдер выбирается в `.env` сервера. Код не меняется: набор переменных и задач один для
всех, различия сервисов вынесены в адаптеры `shared/ai/providers/`. Переключение — правка
`.env`, перезапуск службы и одна команда проверки.

```
node tools/check-provider.js        # проверить связь до перезапуска сервера
sudo systemctl restart career-assistant
```

Инструмент читает `.env`, отправляет одну короткую учебную задачу (извлечь требования из
текста вакансии) и печатает время, токены и результат. Персональные данные не отправляет.

## Политика продукта: только открытые веса

Для продукта используются только модели с открытыми весами. Провайдеры OpenAI, Anthropic и
Google **не допущены**: сервер отклоняет такие настройки при старте и на каждом запросе с
понятной ошибкой, а через маршрутизатор закрытая модель блокируется по имени (`gpt-*`,
`gpt-oss`, `claude*`, `gemini*`). Обход — только `AI_ALLOW_CLOSED_PROVIDERS=1` для
сравнительной оценки на обезличенных данных; в `/api/health` это видно как `policyOk`.

Допущены: `yandex`, `gigachat`, `openai_compatible` (локальная модель), а также хостеры
открытых весов `cerebras`, `groq`, `fireworks`, `together`, `openrouter`. Неизвестное имя
провайдера — ошибка, а не заглушка.

## Что важно до выбора

**Где обрабатываются данные.** Резюме и ответы пользователя — персональные данные.
Отправка их в зарубежный сервис — трансграничная передача по 152-ФЗ. Для продукта с
пользователями из РФ выбирайте `yandex`, `gigachat` или локальную модель. Зарубежные
сервисы годятся для проверки качества на обезличенных примерах.

**Сверены ли формы запросов.** Адаптер Anthropic сверен со справочником. Остальные собраны
по публичным примерам и помечены как несверенные: первый живой вызов покажет, верны ли они.
Инструмент проверки для этого и нужен.

**Изображения.** Ни один из российских сервисов в матрице не заявляет поддержку изображений,
поэтому кадр экрана им не отправляется. Для веб-сервиса это не имеет значения — там
изображений нет.

## Общие переменные

| Переменная | Что это |
| --- | --- |
| `AI_PROVIDER` | `mock` · `yandex` · `gigachat` · `openai_compatible` · `anthropic` · `openai` · `gemini` |
| `AI_MODEL` | Идентификатор модели у провайдера. Если пусто — берётся модель по умолчанию из матрицы |
| `AI_API_KEY` | Ключ или токен доступа. Только в `.env`, права 600 |
| `AI_ENDPOINT` | Адрес сервиса. Нужен для локальной модели и нестандартных адресов |
| `AI_FOLDER_ID` | Только для YandexGPT: идентификатор каталога |
| `AI_LOCALE` | Язык ответа, по умолчанию `ru-RU` |
| `AI_TIMEOUT_MS` | Таймаут запроса, по умолчанию 60000 |

## `mock` — заглушка без сети

```
AI_PROVIDER=mock
```

Работает без ключа и без сети. Требования извлекает из текста вакансии простым правилом,
остальные ответы фиксированные и помечены словом «Заглушка». Для проверки интерфейса и
развёртывания. В шапке страницы — «Сервер · заглушка модели».

## `yandex` — YandexGPT, данные в РФ

```
AI_PROVIDER=yandex
AI_MODEL=yandexgpt-lite
AI_API_KEY=<API-ключ сервисного аккаунта>
AI_FOLDER_ID=<идентификатор каталога>
```

Что нужно: аккаунт в облаке Яндекса, каталог, сервисный аккаунт с ролью для языковых
моделей, API-ключ этого аккаунта. Модель задаётся строкой `gpt://<каталог>/<модель>` —
адаптер собирает её сам из `AI_FOLDER_ID` и `AI_MODEL`. Если у вас уже есть полный `modelUri`,
его можно передать через `AI_MODEL` целиком: адаптер поймёт по префиксу `gpt://`.

Варианты модели: `yandexgpt-lite` дешевле и быстрее, `yandexgpt` точнее. Начинайте с lite,
переходите на старшую, если на проверочном наборе много выдуманных фактов.

Особенности адаптера: сообщение содержит поле `text`, а не `content`; параметры лежат в
`completionOptions`. Форма собрана по публичным примерам — проверьте инструментом.

## `gigachat` — GigaChat, данные в РФ

```
AI_PROVIDER=gigachat
AI_MODEL=GigaChat
AI_AUTH_KEY=<ключ авторизации>
```

Что нужно: аккаунт разработчика, проект, ключ авторизации. Интерфейс совместим с форматом
OpenAI, поэтому используется тот же адаптер с другим адресом.

Две особенности, которые надо знать:

1. **Токен доступа временный, но обновляется сам.** Задайте `AI_AUTH_KEY` — ключ
   авторизации из личного кабинета. Сервер обменяет его на токен доступа через
   `/api/v2/oauth`, закэширует и обновит за минуту до истечения. Форма обмена собрана по
   публичным примерам — первый запуск покажет. Если предпочитаете управлять токеном сами,
   положите его в `AI_API_KEY`: тогда обмена не будет.
2. **Сертификаты.** Сервис работает с российской цепочкой сертификатов. Если проверка
   связи падает с ошибкой TLS, укажите Node путь к корневому сертификату через переменную
   `NODE_EXTRA_CA_CERTS` в `.env` службы. Порядок получения сертификата — в документации
   провайдера.

## `openai_compatible` — локальная или своя модель

```
AI_PROVIDER=openai_compatible
AI_MODEL=<имя модели, как она установлена>
AI_ENDPOINT=http://127.0.0.1:11434/v1/chat/completions
AI_API_KEY=
```

Подходит для Ollama, LM Studio, vLLM и любого сервиса с интерфейсом чата в стиле OpenAI.
Данные не покидают машину. Ключ обычно не нужен.

Ограничения: строгого режима JSON чаще нет, ответ разбирается защищённо; контекст меньше
облачных моделей; изображения не поддерживаются. Качество сильно зависит от модели —
проверяйте на наборе из 20 примеров, а не на одном.

## Хостеры открытых весов — `cerebras`, `groq`, `fireworks`, `together`, `openrouter`

Один формат запроса (совместимый с OpenAI), различаются адрес, имена моделей и расширения.
Адрес берётся из профиля автоматически; `AI_ENDPOINT` нужен только для нестандартного.

```
AI_PROVIDER=groq            # или cerebras | fireworks | together | openrouter
AI_MODEL=<имя модели из каталога хостера, открытые веса>
AI_API_KEY=<ключ>
```

Имена моделей: у Fireworks вида `accounts/fireworks/models/<имя>`, у Together и OpenRouter с
пространством имён (`qwen/…`, `meta-llama/…`). Каталог и доступность модели проверяются живым
запросом — в код цены и списки не зашиты.

Особенности:
- **Расход при потоке** запрашивается через `stream_options.include_usage` и приходит в последнем
  событии. Если хостер его не прислал — в учёте статус «неизвестно», не ноль.
- **OpenRouter**: в тело добавляется `usage: {include: true}` (расход, кэш, стоимость в ответе).
  Объект `provider` (порядок, запрет fallback) можно передать через настройки — это предпочтения
  маршрутизации, а не гарантия задержки.
- **Groq**: параметр рассуждения `reasoning_format` подставляется из профиля, если задан
  в запросе; для остальных хостеров форма параметра зависит от модели и в профиле не задана.
- **Данные за рубежом.** Для резюме с персональными данными это трансграничная передача.

Сайты этих хостеров недоступны из среды разработки: формы собраны по вторичным выдержкам и
помечены как несверенные. Первый вызов `node tools/check-provider.js` покажет расхождения.

## `anthropic` — Claude, данные за рубежом (не допущен для продукта)

```
AI_PROVIDER=anthropic
AI_MODEL=claude-opus-5
AI_API_KEY=<ключ>
```

Модели: `claude-opus-5` — основная; `claude-sonnet-5` — дешевле; `claude-haiku-4-5` — самая
быстрая. Адаптер сверен со справочником: системная инструкция отдельным полем, глубина
рассуждения через `output_config.effort` (для коротких задач — низкая), потоковый вывод для
интервью и подсказок. Отказ модели по классификатору безопасности приходит как отдельная
причина остановки — адаптер его распознаёт.

Данные обрабатываются за пределами РФ: используйте для проверки качества на обезличенных
примерах, не для пользовательских резюме.

## `openai` — OpenAI, данные за рубежом (не допущен для продукта)

```
AI_PROVIDER=openai
AI_MODEL=<идентификатор модели из документации>
AI_API_KEY=<ключ>
```

Форма запроса собрана по общеизвестной схеме и не сверялась. Имя поля для ограничения
длины ответа менялось между версиями интерфейса: адаптер по умолчанию отправляет
`max_completion_tokens`. Если сервис отвечает ошибкой про неизвестное поле, проверьте
документацию своей версии.

## `gemini` — Google Gemini, данные за рубежом (не допущен для продукта)

```
AI_PROVIDER=gemini
AI_MODEL=<идентификатор модели из документации>
AI_API_KEY=<ключ>
```

Форма запроса не сверялась. Особенности: история называется `contents`, роль ассистента —
`model`, системная инструкция — отдельное поле.

## Порядок переключения

1. Правка `.env`.
2. `node tools/check-provider.js` — должно напечатать «Проверка пройдена».
3. `sudo systemctl restart career-assistant`.
4. В браузере: в шапке название сервиса вместо «заглушка».
5. Одна настоящая подготовка руками. Посмотреть на сопоставление глазами: ссылается ли
   модель на конкретные места резюме, не выдумывает ли факты.
6. `journalctl -u career-assistant -f` — записи `ai.task` с временем, попытками и тем,
   что не поместилось в контекст. Без ключа и без текста резюме.

## Если проверка не проходит

| Симптом | Куда смотреть |
| --- | --- |
| Код 401 или 403 | Ключ, права сервисного аккаунта, у GigaChat — истёк ли токен |
| Код 404 | Имя модели или адрес сервиса |
| Код 400 с упоминанием поля | Форма запроса: адаптер несверенного провайдера, см. `shared/ai/providers/` |
| «Сеть недоступна» | Доступ с сервера наружу, TLS-сертификаты у GigaChat |
| Ответ есть, но не JSON | Модель не удержала формат: попробуйте старшую модель провайдера |
| Требования найдены, но не из текста | Модель додумывает: сменить модель или ужесточить промпт в `shared/ai/prompts.js` |

## Добавить нового провайдера

1. Профиль в `shared/ai/capabilities.js`: куда идёт системная инструкция, форма истории,
   поле длины, изображения, поток, регион данных.
2. Адаптер в `shared/ai/providers/<имя>.js` с четырьмя функциями: `toWire`, `fromWire`,
   `streamDelta`, `streamStop`. Образец — `yandex.js`.
3. Регистрация в `shared/ai/providers/index.js`.
4. Проверки в `tests/shared.test.js` на форму запроса и разбор ответа.
5. `node tools/gen-ai-docs.js` — таблица провайдеров в документации обновится сама.
