# Голос → текст: MVP с явным согласием

Реализован отдельный STT-слой `shared/stt/index.js` и общий виджет
`shared/stt/widget.js`. По умолчанию выбран **mock: он НЕ распознаёт речь,
не открывает микрофон и возвращает фиксированную демонстрационную реплику**.
Работающая интеграция с протоколом whisper.cpp предусмотрена в коде; движок и
веса не входят в npm-зависимости. В текущей среде модель не запускалась,
распознавание человеческой речи не подтверждено.

## Источник и разрешения

Первый срез — только текущий входной микрофон ОС: `getUserMedia({audio:true,
video:false})`. Выбор входного устройства пока выполняется в настройках ОС/браузера.
Проверьте, что выбран именно нужный микрофон, а не виртуальный вход с чужой речью.
Системный/meeting audio, `getDisplayMedia`, loopback, распознавание говорящих и
параллельная запись участников не реализованы. `capabilities()` возвращает
`systemAudio:false` на всех ОС и наличие API микрофона; наличие API ещё не
означает наличие устройства или выданного разрешения. Запишите свой вопрос
микрофоном или введите текст вручную. Для записи слышимой через микрофон чужой
речи нужно явное согласие участников. Окна Electron остаются видимыми при
демонстрации экрана, защиты от захвата и скрытого режима нет.

| Среда | Практические условия |
| --- | --- |
| Linux + Electron | Рабочий аудиовход ОС, графическая сессия и доступ Chromium к аудиоустройству. Локальный whisper-server запускается отдельно. Разрешение выдаётся только панели управления после отдельного согласия; камера и окна overlay/consent его не получают. |
| Браузер на компьютере | `mediaDevices.getUserMedia`, Web Audio (`AudioContext`, `createScriptProcessor`), secure context: HTTPS или localhost. Рекомендуемый для проверки маршрут — страница приложения с localhost и STT на том же компьютере. |
| Мобильный браузер | Виджет адаптирован к узкому экрану. Нужны те же API и локальный сервер непосредственно на этом устройстве. `127.0.0.1` телефона не указывает на компьютер; обычному телефону доступен mock или ручной ввод. |
| Удалённая HTTPS-страница | Браузер может запросить доступ к локальной сети или заблокировать HTTP loopback/CORS. Это отображается как ошибка STT; используйте приложение на localhost или Electron. Универсальная совместимость не заявляется. |

Старая демонстрационная «голосовая тренировка» остаётся сценарием без микрофона.
Новый виджет находится внутри начатого **текстового интервью**, а в Electron —
отдельно на панели управления, без обязательного запуска чтения экрана.

## Отдельный локальный движок

Для приложения нужен Node.js >=22.5 и зависимости из основного/desktop README. Для движка нужны Git, C/C++ toolchain, CMake, curl или wget для загрузки и скачанная многоязычная модель whisper.cpp.
Для русского языка используйте `base` или `small`, а не вариант `.en`.
Ни OpenRouter, ни Cerebras для этого этапа не используются.
Команды ниже выполняются пользователем отдельно; обновление приложения не
устанавливает и не запускает STT-сервис. Каталог `data/` исключён из git.

```bash
# Из корня этого репозитория; зависимости и веса остаются внутри data/.
git clone https://github.com/ggml-org/whisper.cpp.git data/whisper.cpp
cmake -S data/whisper.cpp -B data/whisper.cpp/build -DWHISPER_BUILD_SERVER=ON
cmake --build data/whisper.cpp/build --config Release -j 2
bash data/whisper.cpp/models/download-ggml-model.sh base data/whisper.cpp/models
data/whisper.cpp/build/bin/whisper-server -m data/whisper.cpp/models/ggml-base.bin --host 127.0.0.1 --port 8080 -l ru
```

Проверьте `whisper-server --help` для установленной версии. Контракт адаптера:
`POST /inference`, multipart-поля `file` (mono PCM16 WAV, 16 кГц),
`response_format=json`, `language=ru`, `temperature=0`; ответ `{ "text": "..." }`.
Описание: [официальный сервер whisper.cpp](https://github.com/ggml-org/whisper.cpp/tree/master/examples/server).

**Не включайте `--convert`, `--debug-mode`, `--print-realtime` и
`--print-progress`**. WAV уже формируется клиентом: конвертация в серверном
примере создаёт временные файлы; вывод сегментов может раскрыть транскрипт.
Актуальный пример сервера читает WAV из памяти и разрешает CORS; не публикуйте
этот диагностический сервис в Интернет и не запускайте его от root. Источник
этого требования и поведения — [код сервера](https://github.com/ggml-org/whisper.cpp/blob/master/examples/server/server.cpp).
Свой прокси/сборку нужно отдельно проверить на отсутствие записи тел запросов.

В UI выберите «Локальный whisper.cpp» и адрес
`http://127.0.0.1:8080/inference`. Разрешены только HTTP loopback-адреса
`127.0.0.1`, `localhost`, `[::1]`, путь `/inference`, без credentials/query/hash;
редиректы запрещены. Ключ STT для этого локального протокола не нужен. В Electron отдельное согласие также временно разрешает панели доступ к loopback-сети (и прежнее разрешение Chromium `local-network-access`); STT-адаптер всё равно запрещает адреса вне loopback. Отмена отзывает это разрешение.
Веб-страница хранит выбор только до ухода с интервью, не читает серверный `.env`
и не передаёт аудио серверу карьерного помощника.

Electron может получить начальные настройки из окружения процесса:

```bash
STT_PROVIDER=whisper_cpp STT_ENDPOINT=http://127.0.0.1:8080/inference npm --prefix desktop start
```

По умолчанию `STT_PROVIDER=mock`. `.env` автоматически читает только веб-сервер;
для Electron передайте переменные в окружении запуска. Значения можно изменить
в виджете до записи; они не сохраняются на диск. Неизвестный STT-провайдер не
подменяется настоящим распознаванием или текстовой моделью.

## Состояния, границы и данные

1. Отметьте отдельное согласие и нажмите «Записать / повторить».
   `idle → requesting → recording` (в mock явно показано, что микрофон выключен).
   Браузер/ОС может дополнительно запросить разрешение.
2. «Стоп → распознать» отключает дорожки микрофона; затем `transcribing`.
   Через 30 секунд запись автоматически останавливается. Это отдельные реплики,
   а не непрерывный стрим: для следующей нужно ещё раз нажать запись.
3. `ready`: проверьте редактируемый текст, исправьте ошибки, удалите личные данные.
   Только «Отправить фрагмент в AI» передаёт первую часть до 4000 символов;
   оставшиеся части сохраняются в поле для следующих явных отправок.
4. «Отменить / очистить» прекращает запись/транскрипцию, отменяет связанный запрос
   подсказки/интервью и очищает текст. Уход со страницы, скрытие вкладки/минимизация или закрытие окна освобождает
   микрофон. Поздно разрешённый `getUserMedia` немедленно освобождается; сам
   системный диалог разрешения приложение закрыть не может.
5. `error`: отказ в разрешении, отсутствие речи, неверный ответ или недоступность
   движка. Повтор запускает новую запись; старое аудио не хранится для повторной отправки.

Таймаут STT — 60 секунд, только один запрос за раз, без автоматического повтора
аудиозапроса. Запись ограничена 30 секундами и примерно 0,96 МБ PCM WAV, ответ —
128 КиБ и 32000 символами. Текст разделяется по пробелам без разрыва UTF-16 пары.
На слабом CPU модель может не уложиться в таймаут; меньшая модель быстрее, но
хуже распознаёт акценты, шум и термины. Возможны выдуманные слова на тишине,
потеря конца слова на границе реплики; автоматическая оценка достоверности не
реализована. Используется простой ресэмплинг и устаревающий ScriptProcessor;
это MVP, без измеренной гарантии качества/задержки и без фоновой записи.

Аудио, PCM и WAV существуют только в оперативной памяти клиента и локального
движка при указанной конфигурации, не попадают в API интервью, localStorage,
IndexedDB, настройки, журнал или файлы приложения. Освобождение ссылок позволяет
GC удалить буферы; это не гарантия физического стирания памяти/OS swap.
Ошибки STT не показывают тело ответа провайдера. Поля транскрипта и аудио
добавлены в редактирование AI-журналов; произвольные имена в тексте автоматически
не распознаются как PII — перед отправкой пользователь редактирует текст.

Отправленный веб-транскрипт становится обычной репликой кандидата и сохраняется
на сервере по существующим правилам хранения интервью. Отмена не удаляет уже
сохранённую реплику. Если ответ LLM не пришёл, используйте существующее повторение
ответа интервьюера, чтобы не отправить одну реплику дважды. Desktop хранит
контекст подсказок только в памяти, очищает по отмене/закрытию; подсказка по речи
показывается отдельным текстом, без записи в журнал.

## Текст после распознавания

Веб: проверенный фрагмент → прежний `POST /api/interviews/:id/turns` →
`interview.turn`. Сохраняются серверные лимиты/таймауты/AI routing; закрытие SSE
отменяет сигнал провайдера и не добавляет поздний ответ интервьюера.
Electron: проверенный фрагмент → `Session.transcript` → `assistant.hint` с
контекстом подготовки. Вызов не делает скриншот. Минимум 5 секунд между отправками,
одна подсказка за раз, прежние таймауты/повторы общего AI-адаптера.

OpenRouter/Cerebras остаются **текстовыми LLM-провайдерами**. Точную модель
выбирают существующие `AI_MODEL` или профили из `AI_PROFILES_JSON` и
`AI_TASK_ROUTES_JSON`. Например, профиль `fast` с `FAST_PROVIDER=cerebras` и
`FAST_MODEL=<доступный-в-вашем-аккаунте-text-model-id>` может обслуживать
`interview.turn` и `assistant.hint`; профиль OpenRouter с собственным `model`
можно назначить тем же задачам. Этот апгрейд не меняет выбранные ранее модели
и не предполагает доступность конкретного каталожного ID. Конкретный ID —
значение `model` разрешённого профиля для задачи, а не имя STT-модели `base`.
Настройка маршрутизации и ссылки на каталоги: [providers.md](providers.md).
Ключи текстовых сервисов остаются в окружении/некоммитируемом `.env`, в STT-поле
или браузере их нет. Даже при полностью локальном STT отправка текста
зарубежной LLM требует осознанного согласия; это отражено в виджете.

## Проверки и текущие ограничения проверки

```bash
npm run test:stt
npm run test:stt:browser
npm test
npm run build
xvfb-run -a npm run test:desktop
git diff --check
```

Тесты не требуют токенов или установленной Whisper-модели. Unit/in-process E2E
проверяют автомат состояний, отмену, таймаут, WAV и реальные сериализованные
multipart-байты через стандартные `Request/Response`, парсинг ответов, редактирование
логов, а также оба AI-task. Это проверка протокола на фикстурах, не inference.
Browser-тест использует синтетическое устройство Chromium и фикстуру STT;
проверяет ширины 1280/390, разрешения, стоп и отсутствие хранения. Существующие
live/desktop-тесты дополнены прохождением транскрипта через UI.

В песочнице этой реализации HTTP-listen запрещён (`EPERM`), Chromium падает
с `sandbox_host_linux.cc:41`, Electron сообщает `Process failed to launch`.
Поэтому браузерные/desktop-утверждения и настоящий микрофон здесь не выполнены.
Выполнены socketless проверки протокола, WAV и AI-потока. Для подтверждения
реальной речи на рабочем компьютере запустите указанный движок, запишите
собственную согласованную тестовую фразу, проверьте её текст и стоп-индикатор.

## Распознавание на сервере

Третий вариант в виджете — «Сервер Easyjob»: фрагмент WAV (до 1 МБ, 16 кГц моно) уходит
как base64 в `POST /api/stt/transcribe` с cookie сессии и полем `consent: true`. Сервер
пересылает его в whisper.cpp, запущенный рядом с ним (`STT_PROVIDER=whisper_cpp`,
`STT_ENDPOINT` только loopback и путь `/inference`), и возвращает
`{ ok, text, mock, provider, latencyMs }`. При `STT_PROVIDER=mock` текст демонстрационный и
помечен `mock: true`; виджет показывает это как заглушку. Аудио и текст на сервере не
сохраняются; в журнал идут размер, длительность и число знаков. Ошибки: `consent_required`
(400), `bad_audio` (413/422), `stt_unconfigured` (503), `stt_unavailable` (502), `timeout` (504).
`GET /api/stt` отдаёт провайдер и признак `live` без секретов. Маршрут считается дорогим и
попадает под лимит частых запросов к модели. Проверки — `tests/server.test.js`
(поддельный whisper.cpp на loopback) и `tests/stt.test.js` (провайдер `server`).
