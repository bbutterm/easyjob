# Помощник на собеседовании — прототип программы для компьютера

Прозрачное окно поверх экрана: читает выбранный вами экран или окно, находит вопрос
собеседующего и показывает короткое направление ответа.

> **Прототип.** Не установщик и не готовый продукт. Формат распространения, подпись кода,
> обновления и поддержка операционных систем не проработаны.

## Правовая рамка — прочитайте до запуска

Использование помощника на настоящем собеседовании **нужно согласовать с работодателем**.
Многие компании запрещают посторонние подсказки во время интервью; нарушение может привести
к отказу и к отзыву уже сделанного предложения о работе. Кадр экрана может содержать
персональные данные других людей — отправляя его в сервис модели, вы передаёте эти данные
третьей стороне.

Программа требует подтвердить это на экране согласия при первом запуске и не работает,
пока подтверждение не дано.

## Что программа делает и чего не делает

| Делает | Не делает |
| --- | --- |
| Показывает прозрачное окно поверх других окон | Не скрывает окно от захвата и демонстрации экрана |
| Снимает кадр выбранного вами экрана или окна | Не читает экран в фоне и без запущенной сессии |
| Отправляет кадр или текст выбранному вами сервису модели | Не включает микрофон без отдельного согласия; не захватывает системный звук |
| Держит данные сессии в памяти | Не сохраняет кадры, распознанный текст и подсказки на диск |
| Показывает индикатор чтения и название источника | Не прячет свой процесс и не обходит правила площадок |

Отдельно: вызов `setContentProtection` намеренно **не используется**. Окно видно собеседнику,
если вы демонстрируете экран. Скрывать его — это обход правил собеседования, а не функция.

## Запуск

```
cd desktop
npm install
npm start
```

Первый запуск открывает экран согласия. После подтверждения открывается панель управления.

## Порядок работы

1. **Сервис модели.** Выберите провайдера и модель. По умолчанию стоит заглушка без сети —
   она позволяет пройти весь цикл, ничего не подключая и не тратя денег.
2. **Ключ доступа.** Введите в панели или передайте через переменную окружения
   `ASSISTANT_API_KEY`. Ключ хранится **только в памяти** программы и исчезает при закрытии.
3. **Подготовка.** Вставьте JSON с резюме, вакансией и слабыми местами — под них подбирается
   подсказка. Кнопка «Подставить пример» заполняет образец. В готовом продукте это приходит
   из веб-сервиса.
4. **Источник.** Нажмите «Показать список окон» и выберите экран или окно. До выбора и
   запуска ничего не снимается.
5. **Сессия.** «Начать сессию» открывает прозрачное окно и запускает цикл. «Спросить сейчас»
   запрашивает подсказку вне очереди. «Остановить» завершает сессию и очищает память.

## Как читается экран

Три режима, переключаются в панели:

| Режим | Что происходит | Когда применим |
| --- | --- | --- |
| `mock` | Фиксированные ответы, сети нет | Проверка интерфейса и цикла |
| `vision` | Кадр отправляется мультимодальной модели, она сама читает текст | Провайдер поддерживает изображения |
| `text` | Текст распознаётся локально, в модель уходит только он | **В прототипе не подключено** |

Режим `text` — точка расширения в `lib/ocr.js`. Он предпочтительнее для локальных моделей
без поддержки изображений и дешевле по трафику, но требует локальной библиотеки распознавания.
Интерфейс зафиксирован, чтобы подключение не потребовало менять сессию.

## Цикл сессии

```
кадр источника
   ↓  задача screen.extract
вопрос собеседующего (или null — тогда запрос подсказки не делается)
   ↓  задача assistant.hint
направление ответа → прозрачное окно
```

Обе задачи идут через общий слой `shared/ai`, поэтому программа и веб-сервис используют
один набор переменных и одни правила. Подсказка ограничена примерно 40 словами: длинную
невозможно прочитать в разговоре.

## Контекст

Контекст собирается `shared/context/store.js` и разложен на слои по скорости изменения:
профессия и правила — резюме и вакансия — реплики сессии — текущий кадр. Стабильное идёт
в начало запроса (это позволяет кэшировать префикс), изменчивое — в конец. При нехватке
бюджета первым отбрасывается кадр, затем объёмные исходные тексты; слабые места
сопоставления сохраняются до последнего. Подробнее — `docs/context-model.md`.

## Структура

```
main.js              главный процесс: окна, захват кадра, обмен с окнами
preload.js           мост между окнами и главным процессом (contextIsolation)
lib/settings.js      настройки; ключ доступа только в памяти
lib/session.js       цикл сессии, сборка контекста, запросы
lib/ocr.js           точка расширения для распознавания текста
renderer/consent.html   экран согласия при первом запуске
renderer/control.html   панель управления
renderer/overlay.html   прозрачное окно с подсказкой
```

## Проверка

```
xvfb-run -a node ../tests/desktop.test.js     # Linux без графической оболочки
node ../tests/desktop.test.js                 # обычная система
```

Тест запускает настоящее приложение и проверяет 28 условий: экран согласия и блокировку
кнопки, отсутствие ключа на диске, список источников, цикл сессии, прозрачное окно,
остановку и отсутствие сохранённых кадров.

В среде без графической оболочки система не отдаёт ни одного источника захвата. Для проверки
цикла в таком окружении есть режим `ASSISTANT_FAKE_CAPTURE=1`: он добавляет тестовый источник,
помеченный в интерфейсе как «тестовый», и отдаёт синтетический кадр вместо снимка экрана.
По умолчанию режим выключен.

## Что не сделано

- Распознавание текста локально (режим `text`).
- Установщик, подпись кода, обновления, поддержка macOS и Windows не проверялись:
  прототип запускался только на Linux.
- Безопасное хранение ключа доступа между запусками.
- Связь с веб-сервисом: подготовка вставляется вручную, единого аккаунта нет.
- Потоковый вывод подсказки — сейчас ответ приходит целиком.
- Определение, кто говорит на экране, и отсечение своих же реплик.
- Ограничение расходов: счётчик запросов есть, лимитов и предупреждений нет.

## STT: запись микрофона по согласию

Отдельный виджет в панели работает без экранной сессии: запись до 30 секунд → стоп → локальный whisper.cpp → проверка текста → `assistant.hint`. Mock не распознаёт и не включает микрофон. Условия для Linux, `STT_PROVIDER`/`STT_ENDPOINT`, запуск отдельного движка и ограничения проверки описаны в [docs/stt.md](../docs/stt.md).
