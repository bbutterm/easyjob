# Карьерный помощник — кликабельный макет

Демонстрационный frontend-прототип русскоязычного сервиса подготовки к поиску работы и
собеседованиям. Это **макет интерфейса**, а не работающий продукт.

Работает в двух режимах:

- **Демо** — `index.html` открыт как файл. Данные в памяти вкладки, ответы модели имитируются
  помеченными демонстрационными данными. Регистрации и сервера не нужно.
- **Сервер** — страница отдана `server/`. Данные в базе SQLite, кнопки ходят в API, ответы
  приходят от выбранного провайдера модели или от серверной заглушки, пока ключ не задан.
  Развёртывание — `docs/deploy.md`.

> Платежи, чтение PDF и DOCX, вход по почте пока не подключены. Голос → текст доступен как MVP с отдельным локальным STT (см. ниже). Помощник на
> собеседовании заморожен по итогам аудита.

## Запуск

Сборщик, npm-зависимости и сеть не нужны.

```
# вариант 1 — просто открыть файл в браузере
open index.html        # macOS
xdg-open index.html    # Linux

# вариант 2 — локальный сервер, если браузер ограничивает file://
python3 -m http.server 8000
# затем http://localhost:8000/
```

`index.html` в корне — автономная сборка: весь CSS и JavaScript встроены внутрь одного файла.
Его можно переслать одним вложением, и он откроется без интернета.

## Структура

```
index.html          автономная сборка макета (открывать этот файл)
build.js            сборка index.html из src/ — node build.js

src/                исходники веб-макета
  index.html        разметка-оболочка со ссылками на отдельные файлы
  styles.css        токены оформления и компоненты
  professions.js    библиотека профессий и общие блоки
  data.js           сборка демонстрационного комплекта под профессию
  state.js          состояние макета и правила хранения
  ui.js             диалоги, уведомления, поля, экранирование
  screens-core.js   вход, обзор, резюме, вакансии
  screens-prep.js   сопоставление, вопросы, интервью, помощник, тарифы, настройки
  app.js            hash-маршрутизация и обработка действий

server/             сервер: API, сессии, база SQLite, учёт расходов
  index.js          точка входа, статика, проверка Origin
  lib/db.js         схема и запросы (встроенный SQLite Node.js)
  lib/ai.js         сборка контекста из базы и вызов shared/ai; здесь живёт ключ
  routes/api.js     резюме, вакансии, подготовки, вопросы, интервью потоком, карточка
deploy/             systemd, nginx, скрипт обновления

shared/             общий слой для веба и программы для компьютера
  ai/variables.js   каталог переменных и задач для модели
  ai/capabilities.js различия провайдеров
  ai/prompts.js     сборка текста запроса
  ai/request.js     нормализованный запрос, скрытие ПДн, разбор ответа
  ai/providers/     адаптеры Anthropic, OpenAI, Gemini, заглушка
  context/store.js  слои контекста, бюджет, усечение, свёртка

desktop/            прототип программы для компьютера (Electron)
  main.js           окна, захват кадра, обмен с окнами
  lib/session.js    цикл сессии
  renderer/         экран согласия, панель управления, прозрачное окно

tools/gen-ai-docs.js  генерация docs/ai-variables.md из кода
tools/check-provider.js проверка связи с провайдером модели по .env
tests/check.js        сквозная проверка макета в браузере (демо-режим)
tests/live.test.js    сквозная проверка макета против сервера (режим сервера)
tests/server.test.js  проверка API в памяти
tests/shared.test.js  проверки общего слоя
tests/desktop.test.js сквозная проверка программы для компьютера
docs/screen-map.md    карта экранов и переходов
docs/stubs.md         перечень заглушек
docs/ai-variables.md  переменные и задачи для модели (генерируется)
docs/context-model.md хранение и передача контекста
docs/test-report.md   отчёт о выполненных проверках
docs/screenshots/     снимки экранов
```

Работать с кодом удобнее в `src/`. После правок нужно пересобрать корневой файл:

```
node build.js
```

Каталог `src/` тоже открывается напрямую (`src/index.html`) — файлы подключаются
обычными тегами `<link>` и `<script>`, без модулей и без сборщика.

## Что можно пройти в макете

1. Начальная страница → выбор сценария → мастер резюме → предпросмотр → вакансия →
   сопоставление → вопросы → текстовое интервью → итог.
2. Загрузка готового резюме с устройства → объяснение ограничений → образец разбора →
   принятие и отклонение предложений.
3. Изменение резюме или вакансии → прежний отчёт помечается как относящийся к
   предыдущей версии → пересборка демо.
4. Голосовое интервью: состояния «Слушаю», «Готовлю ответ», «Отвечаю», «Пауза»,
   «Связь потеряна», завершение — без обращения к микрофону.
5. Помощник на собеседовании: выбор подготовки, заглушка скачивания, демо-статусы
   подключения, примеры подсказок, предупреждение о правилах и согласии участников.
6. Тарифы: переключение демо-уровня, блокировка разделов с объяснением, заглушка оплаты,
   состояние исчерпанного лимита.
7. Пустые состояния, ошибки форм, диалоги подтверждения, сброс демо, тёмная тема.

Панель «Состояния демо» в правом нижнем углу переключает сценарии
(пусто / заполнено / загрузка / ошибка / лимит) и демо-тариф. Она свёрнута по умолчанию
и не является частью продукта.

## Ограничения прототипа

- В автономном file-демо настоящего ИИ нет. Все «результаты анализа» в нём — фиксированные образцы,
  собранные под выбранную профессию. Они **не подстраиваются** под введённый текст.
  В HTTP-режиме запросы выполняет сервер через настроенный провайдер; источник результата подписан.
- В HTTP-режиме читаются TXT, DOCX (Python 3) и текстовые PDF (Python 3 + pypdf): до 2 МБ / 40 000 символов. DOC/RTF требуют конвертации; OCR нет. Исходные байты не сохраняются. В file-демо чтение недоступно. Проверки и зависимости: `docs/REAL_TEST_GUIDE.md`.
- Получение вакансии по ссылке работает только в режиме сервера (`docs/vacancy-import.md`); автономный макет сетевых запросов не выполняет.
- Авторизации нет. Пароли не собираются, письма не отправляются.
- Платежей нет. Цены и лимиты не определены, названия тарифов рабочие.
- В макете кнопка «Скачать помощник» остаётся заглушкой: готового установщика нет.
  Работающий прототип программы для компьютера лежит в `desktop/` и запускается из
  исходников — см. `desktop/README.md`.
- Старые демо-сценарии не запрашивают микрофон. Новый виджет в текстовом интервью записывает микрофон только после отдельного согласия; синтеза речи нет.
- Введённые данные хранятся только в памяти вкладки и сбрасываются после перезагрузки.
  В `localStorage` сохраняются исключительно тема, выбранный демо-сценарий, демо-тариф и
  состояние демо-панели — ни резюме, ни файлов, ни токенов, ни паролей.
- Внешние шрифты, CDN, аналитика и AI SDK не подключаются.
- Тексты о приватности — черновик формулировок, а не юридически готовая политика.
- Все персоны, компании и вакансии вымышлены и созданы для демонстрации.

## Профессии

Продукт не привязан к одной профессии. В `src/professions.js` есть готовые комплекты для
восьми профессий из разных отраслей — от повара и водителя до разработчика и медсестры.
Профессия в мастере вписывается свободно: список служит подсказкой, а не ограничением.
Для профессии вне библиотеки собирается общий комплект с её названием и честной пометкой.

## Слой запросов к модели

`shared/ai` — общий для веб-сервиса и программы для компьютера. Набор переменных и задач
один для всех провайдеров, различия сервисов вынесены в адаптеры:

- **53 переменные** в 9 группах, **10 задач** (разбор резюме, сопоставление, вопросы,
  реплика интервьюера, итог, чтение экрана, подсказка) — `docs/ai-variables.md`;
- **5 провайдеров**: Anthropic, OpenAI-совместимые, Gemini, локальная модель, заглушка;
- контекст разложен на слои по скорости изменения — `docs/context-model.md`.

Политика продукта — только модели с открытыми весами: OpenAI, Anthropic и Google не допущены,
сервер отклоняет их с понятной ошибкой. Допущены YandexGPT, GigaChat, локальная модель и хостеры
открытых весов Cerebras, Groq, Fireworks, Together, OpenRouter. Формы запросов к хостерам
собраны по вторичным источникам и **требуют проверки перед боевым запуском** — это отмечено в
таблице провайдеров. Как подключить и переключить провайдера —
`docs/providers.md`; проверка связи — `node tools/check-provider.js`.

Единый сценарий реального тестирования двух контуров, моделей Qwen, Whisper/STT,
admin-расходов и критериев приёмки: `docs/REAL_TEST_GUIDE.md`.

## Программа для компьютера

`desktop/` — работающий прототип помощника на собеседовании: прозрачное окно поверх экрана,
чтение выбранного источника по явному запуску, запросы через общий слой. Запуск, правовая
рамка и ограничения — в `desktop/README.md`.

Ключевое: окно **не скрывается** от захвата и демонстрации экрана; микрофон записывается только по отдельному согласию,
кадры и подсказки на диск не пишутся, а первый запуск требует подтвердить, что использование
согласовано с работодателем.

## Аудит

По проекту проведены два независимых аудита (сентябрь 2026):

- `docs/audit-summary.md` — **выжимка**: главные выводы, где аудиты сошлись, план действий.
- `docs/audit-technical.md` — технический разбор: 5 блокеров, 14 важных находок с путями и
  строками, архитектурный вердикт, оценка стоимости эксплуатации.
- `docs/audit-market.md` — рынок, конкуренты, правовая сторона, юнит-экономика, тарифы.
- `docs/security-review.md` — проверка безопасности сервера перед запуском; критичные и
  важные находки исправлены, на каждую есть регрессия.

Ключевой вывод обоих: помощник на собеседовании должен быть закрыт, а не доработан; начинать
следует с фундамента разработки и минимального публичного веб-инструмента. Подробности и
оговорки по достоверности данных — в выжимке.

По итогам аудита выполнено семь итераций (`docs/iterations.md`): фундамент разработки и CI,
три подтверждённых бага, минимизация данных и защита от подмены инструкций, устойчивость
сети, провайдеры с обработкой данных в РФ, карточка подготовки как честная замена помощнику.
Сам помощник не тронут: решение о нём за владельцем.

## Проверка

```
npm install                                # зависимости проверок
npm start                                  # сервер на http://127.0.0.1:3000 (провайдер — заглушка)
npm test                                   # общий слой + сервер + макет в обоих режимах
npm run test:shared                        # общий слой, 85 проверок, без сети
npm run test:context                       # управление контекстом, 19 проверок, без сети
npm run test:server                        # API в памяти, 64 проверки, без сети
npm run test:web                           # макет в браузере, демо-режим, 73 проверки
npm run test:live                          # макет против сервера, режим сервера, 26 проверок
xvfb-run -a npm run test:desktop           # программа для компьютера, 28 проверок
npm run docs                               # перегенерация docs/ai-variables.md
npm run screenshots                        # обновить снимки экранов
```

Всего 295 проверок. Ни одна не ходит в сеть: провайдер модели везде заглушка.

Программе для компьютера дополнительно нужен `electron` (`npm install --prefix desktop`).
Проверки выполняются в CI при каждом push. Результат последнего прогона —
в `docs/test-report.md`, разбор изменений по итерациям — в `docs/iterations.md`.

## Голос → текст (STT MVP)

В начатом текстовом интервью и панели Electron добавлены согласие, кнопки записи/стопа, видимые состояния и редактируемый транскрипт. Источник — только микрофон; системный звук не поддерживается. По умолчанию включена заглушка, которая **не распознаёт речь** и не открывает микрофон. Настоящий путь требует отдельного локального whisper.cpp сервера. Аудио не сохраняется приложением, текст передаётся в прежний `interview.turn` / `assistant.hint` по нажатию.

[Точные зависимости, настройка, ограничения Linux/Electron/браузера и проверки](docs/stt.md). Реальная речь в текущей песочнице не проверена; OpenRouter/Cerebras обрабатывают только текст после отдельного STT.

Учёт расходов, карта этапов A/B, рекомендуемые модели и чеклист: [docs/usage.md](docs/usage.md).

### Quick Start после входа

Для HTTP-аккаунтов добавлен защищённый `#/quickstart`: первый вход в этом браузере
без прежней работы открывает мастер; регистрация — тоже. Повторный вход открывает
обзор. В меню доступны «Продолжить Quick Start» и «Начать Quick Start заново».
Путь: согласие и приватность → резюме → AI-проверка → вакансия → требования и
сопоставление → вопросы и необязательный ответ → текстовая тренировка → отдельный
следующий этап live/STT. Шаги используют серверные действия; ошибки не считаются
успехом. Доступны Назад, Продолжить, пропуск и продолжение позже, обычная навигация
остаётся доступной. Автономное `file://`-демо не требует аккаунта.

Статус хранится локально под серверным ID пользователя, без исходных текстов,
ответов или секретов. Ограничения этого подхода, точные действия и тестовый
чеклист: [docs/quickstart.md](docs/quickstart.md).

Проверки: `npm run test:quickstart` (без сокетов, реальные обработчики API и mock AI),
`npm run test:quickstart:browser` (HTTP + Chromium, 1440/390/360 px), `npm run test:all`.
